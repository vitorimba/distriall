## Story
**As a** Joao (entregador),
**I want** ver uma lista simples dos clientes que preciso entregar hoje, com endereco e um botao grande para marcar como entregue,
**so that** eu consiga fazer as entregas sem confusao e sem precisar pedir ajuda do Tiago.

## Acceptance Criteria
1. Tela simplificada acessivel APENAS pelo perfil "entregador" — rota separada `/driver`
2. Lista de pedidos do dia com status "Carregado", ordenados pela sequencia de rota definida pelo admin
3. Cada item mostra: nome do cliente (fonte GRANDE), endereco, forma de pagamento, lista resumida de produtos (nome + qtd)
4. Botao GIGANTE "ENTREGUE" (verde, ocupa largura total, minimo 60px altura) que muda status do pedido para "Entregue"
5. Campo para anotar observacao na entrega (ex: "recebeu Dona Maria no lugar do Sr. Jose") — aparece ao clicar em "ENTREGUE" como passo opcional
6. Interface com fontes grandes (minimo 18px body, 24px titulos), alto contraste, ZERO menus, ZERO navegacao complexa
7. Realtime: quando admin adiciona/remove pedido da rota, a lista do Joao atualiza automaticamente

## Dev Notes

### CRITICO: Perfil do Usuario (Joao)

**Joao tem BAIXISSIMA familiaridade com tecnologia.** A interface DEVE ser:

- **ZERO menus** — nenhum hamburger, nenhum dropdown, nenhum bottom-nav
- **ZERO navegacao** — tudo em UMA UNICA TELA. Joao nao navega entre paginas.
- **Botoes GIGANTES** — minimo 60px de altura, texto em 20px+, area de toque generosa
- **Fontes GRANDES** — body 18px, titulos 24px, nome do cliente 28px
- **Cores obvias** — verde = entregue, branco = pendente, cinza = ja feito
- **Sem precos** — entregador nao precisa e nao deve ver valores financeiros
- **Sem opcoes** — nao perguntar "tem certeza?", apenas confirmar com 1 tap
- **Feedback imediato** — animacao visual ao marcar como entregue

Pense em um app para uma pessoa que mal usa WhatsApp. Cada interacao deve ser OBVIA.

### Database Tables Envolvidas

Tabela `deliveries` (rota do dia):

```sql
CREATE TABLE public.deliveries (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  account_id UUID NOT NULL REFERENCES public.accounts(id) ON DELETE CASCADE,
  driver_id UUID NOT NULL REFERENCES public.users(id),
  delivery_date DATE NOT NULL,
  status TEXT NOT NULL DEFAULT 'pendente'
    CHECK (status IN ('pendente', 'em_rota', 'concluida')),
  notes TEXT,
  started_at TIMESTAMPTZ,
  completed_at TIMESTAMPTZ,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

Tabela `delivery_items` (pedidos na rota):

```sql
CREATE TABLE public.delivery_items (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  delivery_id UUID NOT NULL REFERENCES public.deliveries(id) ON DELETE CASCADE,
  order_id UUID NOT NULL REFERENCES public.orders(id),
  sequence INTEGER NOT NULL,           -- posicao na rota
  status TEXT NOT NULL DEFAULT 'pendente'
    CHECK (status IN ('pendente', 'entregue', 'nao_entregue')),
  observation TEXT,                     -- "recebeu Dona Maria"
  delivered_at TIMESTAMPTZ,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE(delivery_id, order_id)
);
```

### RLS Policies Especificas do Entregador

```sql
-- Entregador so ve deliveries atribuidas a ele
CREATE POLICY "Drivers can only view their own deliveries"
  ON public.deliveries FOR SELECT
  USING (
    (get_user_role_in_account(account_id) IN ('admin', 'vendedor'))
    OR
    (driver_id = auth.uid())
  );

-- Entregador pode atualizar status das suas deliveries
CREATE POLICY "Drivers can update their own deliveries"
  ON public.deliveries FOR UPDATE
  USING (driver_id = auth.uid() OR get_user_role_in_account(account_id) = 'admin');

-- Entregador pode atualizar delivery_items das suas rotas
CREATE POLICY "Drivers can update their delivery items"
  ON public.delivery_items FOR UPDATE
  USING (
    delivery_id IN (
      SELECT id FROM deliveries WHERE driver_id = auth.uid()
    )
  );
```

### Query Principal

```typescript
// Hook: use-driver-deliveries.ts
const { data } = await supabase
  .from('delivery_items')
  .select(`
    id,
    sequence,
    status,
    observation,
    delivered_at,
    order:orders!inner(
      id,
      status,
      payment_method,
      total,
      client:clients!inner(
        name,
        address,
        neighborhood,
        city
      ),
      items:order_items(
        product_name,
        variant_name,
        quantity
      )
    ),
    delivery:deliveries!inner(
      id,
      delivery_date,
      driver_id
    )
  `)
  .eq('delivery.driver_id', userId)
  .eq('delivery.delivery_date', today)
  .order('sequence', { ascending: true });
```

### Realtime Subscription

```typescript
supabase
  .channel('driver-deliveries')
  .on('postgres_changes', {
    event: '*',
    schema: 'public',
    table: 'delivery_items',
    filter: `delivery_id=eq.${deliveryId}`
  }, (payload) => {
    // Refresh delivery list
    refetchDeliveries();
  })
  .subscribe();
```

### Fluxo de Marcar Entrega

1. Joao toca "ENTREGUE" no card
2. Sheet sobe do fundo com textarea para observacao (placeholder: "Alguma observacao? (opcional)")
3. Joao pode ignorar e tocar "CONFIRMAR ENTREGA" (botao verde gigante)
4. OU digitar observacao e depois tocar "CONFIRMAR ENTREGA"
5. Sistema atualiza: `delivery_items.status = 'entregue'`, `delivery_items.delivered_at = now()`
6. Sistema tambem atualiza: `orders.status = 'entregue'`, `orders.delivered_at = now()`
7. Card move para secao "Entregues" com animacao suave e checkmark verde
8. Toast: "Entrega confirmada!"
