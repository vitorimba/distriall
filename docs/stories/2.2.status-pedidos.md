## Story
**As a** Tiago,
**I want** que cada pedido tenha status claros (Lancado, Confirmado, Carregado, Entregue) com badges visuais coloridos,
**so that** eu saiba exatamente em que estagio cada pedido esta sem confusao.

## Acceptance Criteria
1. Campo `status` no pedido com valores: `lancado`, `confirmado`, `carregado`, `entregue` (e `cancelado`)
2. Transicoes permitidas: lancado->confirmado, confirmado->carregado, carregado->entregue
3. Transicao reversa permitida: qualquer status pode voltar ao anterior (exceto entregue->lancado direto)
4. Filtro de pedidos por status na lista (chips de filtro horizontal scrollable)
5. Badges visuais coloridos por status: Lancado=cinza, Confirmado=azul, Carregado=amarelo, Entregue=verde
6. Confirmacao em lote: selecionar varios pedidos e confirmar/carregar de uma vez
7. Timestamps automaticos: `confirmed_at`, `loaded_at`, `delivered_at` preenchidos na transicao

## Dev Notes

### Status Machine

```
                      +-> cancelado (de qualquer status)
                      |
lancado <-> confirmado <-> carregado <-> entregue
  (cinza)    (azul)        (amarelo)     (verde)
```

Transicoes validas (forward): lancado->confirmado, confirmado->carregado, carregado->entregue
Transicoes validas (reverse): confirmado->lancado, carregado->confirmado, entregue->carregado
NAO permitido: entregue->lancado (pular 2 niveis)

### Supabase Function: `transition_order_status`

```sql
CREATE OR REPLACE FUNCTION public.transition_order_status(
  p_order_id UUID,
  p_new_status TEXT
) RETURNS VOID AS $$
DECLARE
  v_current_status TEXT;
  v_valid_transitions JSONB := '{
    "lancado": ["confirmado", "cancelado"],
    "confirmado": ["lancado", "carregado", "cancelado"],
    "carregado": ["confirmado", "entregue", "cancelado"],
    "entregue": ["carregado"]
  }'::JSONB;
BEGIN
  SELECT status INTO v_current_status FROM public.orders WHERE id = p_order_id;

  IF NOT (v_valid_transitions->v_current_status) ? p_new_status THEN
    RAISE EXCEPTION 'Invalid transition from % to %', v_current_status, p_new_status;
  END IF;

  UPDATE public.orders SET
    status = p_new_status,
    confirmed_at = CASE WHEN p_new_status = 'confirmado' THEN now()
                        WHEN p_new_status = 'lancado' THEN NULL
                        ELSE confirmed_at END,
    loaded_at = CASE WHEN p_new_status = 'carregado' THEN now()
                     WHEN p_new_status IN ('lancado', 'confirmado') THEN NULL
                     ELSE loaded_at END,
    delivered_at = CASE WHEN p_new_status = 'entregue' THEN now()
                       WHEN p_new_status IN ('lancado', 'confirmado', 'carregado') THEN NULL
                       ELSE delivered_at END,
    cancelled_at = CASE WHEN p_new_status = 'cancelado' THEN now() ELSE cancelled_at END,
    updated_at = now()
  WHERE id = p_order_id;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;
```

let query = supabase
  .from('orders')
  .select('*, client:clients(name), items:order_items(count)')
  .order('created_at', { ascending: false });

// Filtro por conta (se nao for "Todas")
if (accountId !== 'all') {
  query = query.eq('account_id', accountId);
