## Story
**As a** administrador do sistema,
**I want** que o banco suporte clientes PF/PJ com multiplos enderecos estruturados,
**so that** o sistema possa emitir NF-e, auto-preencher dados e rastrear enderecos de entrega.

## Scope
### IN
- ALTER `clients`: adicionar `type`, `document`, `state_registration`, `email`
- CREATE `client_addresses` com todos os campos estruturados
- Indices parciais para unicidade de `is_fiscal` e `is_default_delivery`
- RLS policies para `client_addresses` (mesmo padrao de `clients`)
- Trigger `updated_at` para `client_addresses`
- ALTER `orders`: adicionar `delivery_address_id`, `delivery_address_snapshot`, `fiscal_address_snapshot`

### OUT
- Migracao de dados existentes (Story 7.2)
- UI/frontend (Stories 7.4-7.6)
- Alteracao nas funcoes create_order/update_order (Story 7.7)

## Dependencies
- Story 1.5 (clientes basico) — Done

## Complexity
- **Estimate:** M
- **Points:** 5
- **Rationale:** Migration SQL com indices parciais e RLS — padrao ja estabelecido no projeto

## Risks
- **R1:** Indices parciais podem conflitar com dados existentes. **Mitigacao:** Dados existentes nao tem `is_fiscal=true`, entao indice parcial nao bloqueia.
- **R2:** ALTER em tabela com dados em producao. **Mitigacao:** Campos novos sao nullable, sem risco.

## Acceptance Criteria
1. **Given** a migration executada, **When** inspeciono `clients`, **Then** vejo colunas `type`, `document`, `state_registration`, `email`
2. **Given** a migration executada, **When** inspeciono `client_addresses`, **Then** vejo todas as colunas (label, cep, street, number, complement, neighborhood, city, state, is_fiscal, is_default_delivery, is_active)
3. **Given** um cliente com 2 enderecos ativos, **When** tento marcar ambos como `is_fiscal=true`, **Then** o banco rejeita com erro de unicidade
4. **Given** um cliente com 1 endereco fiscal ativo e 1 inativo, **When** marco o inativo como fiscal, **Then** o banco aceita (indice parcial filtra `is_active=true`)
5. **Given** um usuario autenticado, **When** consulto `client_addresses`, **Then** so vejo enderecos do meu account (RLS)
6. **Given** a migration executada, **When** inspeciono `orders`, **Then** vejo colunas `delivery_address_id`, `delivery_address_snapshot`, `fiscal_address_snapshot`

### Detalhes da migration
```sql
-- ALTER clients
ALTER TABLE clients ADD COLUMN type TEXT CHECK (type IN ('pf', 'pj')) DEFAULT 'pf';
ALTER TABLE clients ADD COLUMN document TEXT; -- CPF ou CNPJ, so digitos
ALTER TABLE clients ADD COLUMN state_registration TEXT; -- IE
ALTER TABLE clients ADD COLUMN email TEXT;

-- CREATE client_addresses
CREATE TABLE client_addresses (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  client_id UUID NOT NULL REFERENCES clients(id) ON DELETE CASCADE,
  account_id UUID NOT NULL REFERENCES accounts(id) ON DELETE CASCADE,
  label TEXT NOT NULL DEFAULT 'Principal',
  cep TEXT, -- 8 digitos
  street TEXT,
  number TEXT,
  complement TEXT,
  neighborhood TEXT,
  city TEXT,
  state TEXT, -- UF 2 chars
  is_fiscal BOOLEAN DEFAULT false,
  is_default_delivery BOOLEAN DEFAULT false,
  is_active BOOLEAN DEFAULT true,
  created_at TIMESTAMPTZ DEFAULT now(),
  updated_at TIMESTAMPTZ DEFAULT now()
);

-- Indices parciais
CREATE UNIQUE INDEX idx_client_addresses_fiscal
  ON client_addresses (client_id)
  WHERE is_fiscal = true AND is_active = true;

CREATE UNIQUE INDEX idx_client_addresses_delivery
  ON client_addresses (client_id)
  WHERE is_default_delivery = true AND is_active = true;

-- ALTER orders
ALTER TABLE orders ADD COLUMN delivery_address_id UUID REFERENCES client_addresses(id);
ALTER TABLE orders ADD COLUMN delivery_address_snapshot JSONB;
ALTER TABLE orders ADD COLUMN fiscal_address_snapshot JSONB;
```
