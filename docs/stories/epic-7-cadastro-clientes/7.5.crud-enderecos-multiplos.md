## Story
**As a** vendedor,
**I want** cadastrar multiplos enderecos para um cliente com rotulos livres e flags de fiscal/entrega,
**so that** clientes PJ com filiais sejam atendidos corretamente e o endereco da NF-e seja rastreavel.

## Scope
### IN
- Lista de enderecos inline no form do cliente (accordion/cards)
- Botao "Adicionar endereco" abre form inline ou modal
- Cada endereco: label, CEP (com auto-fill ViaCEP), logradouro, numero, complemento, bairro, cidade, UF
- Toggle `is_fiscal` (radio — max 1 ativo por cliente)
- Toggle `is_default_delivery` (radio — max 1 ativo por cliente)
- Soft delete (botao "Desativar" em vez de excluir)
- Reativacao de enderecos inativos
- Auto-fill CEP via hook `useCepLookup` (Story 7.3)
- Funcao pura `getEffectiveFiscalAddress`: fiscal explicito OU primeiro ativo como fallback

### OUT
- Seletor de endereco no pedido (Story 7.6)

## Dependencies
- Story 7.1 — tabela `client_addresses`
- Story 7.2 — dados migrados
- Story 7.3 — hook `useCepLookup`
- Story 7.4 — form base do cliente

## Complexity
- **Estimate:** L
- **Points:** 8
- **Rationale:** CRUD completo com logica de flags mutuamente exclusivas, soft delete, auto-fill CEP

## Risks
- **R1:** Toggle fiscal/delivery confuso para usuario. **Mitigacao:** UI clara com badges visuais "Fiscal" e "Entrega Padrao".
- **R2:** Indices parciais rejeitam operacao silenciosamente. **Mitigacao:** Tratar erro do banco e exibir mensagem clara ("Ja existe um endereco fiscal ativo").

## Acceptance Criteria
1. **Given** form do cliente aberto, **When** clico "Adicionar endereco", **Then** form de endereco aparece com campo label e campos de endereco
2. **Given** CEP digitado com 8 digitos, **When** perco foco, **Then** auto-preenche logradouro, bairro, cidade, UF (se campos vazios)
3. **Given** 3 enderecos cadastrados, **When** marco o 2o como fiscal, **Then** o 1o perde o flag fiscal automaticamente (ou banco rejeita e UI desmarca o anterior)
4. **Given** endereco com `is_default_delivery=true`, **When** marco outro como delivery, **Then** o anterior perde o flag
5. **Given** endereco ativo, **When** clico "Desativar", **Then** endereco fica `is_active=false` e some da lista principal (mas aparece em "Inativos")
6. **Given** endereco inativo, **When** clico "Reativar", **Then** volta a `is_active=true` e aparece na lista principal
7. **Given** cliente sem endereco fiscal explicito, **When** chamo `getEffectiveFiscalAddress`, **Then** retorna o primeiro endereco ativo como fallback
8. **Given** cliente com endereco fiscal explicito, **When** chamo `getEffectiveFiscalAddress`, **Then** retorna o endereco marcado como fiscal

### Logica de flags mutuamente exclusivas
Antes de marcar `is_fiscal=true`, desmarcar o anterior:
```typescript
// Desmarcar fiscal anterior
await supabase
  .from('client_addresses')
  .update({ is_fiscal: false })
  .eq('client_id', clientId)
  .eq('is_active', true)
  .eq('is_fiscal', true);

// Marcar novo
await supabase
  .from('client_addresses')
  .update({ is_fiscal: true })
  .eq('id', addressId);
```
