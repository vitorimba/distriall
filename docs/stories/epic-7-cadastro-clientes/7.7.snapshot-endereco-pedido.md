## Story
**As a** administrador,
**I want** que cada pedido registre uma copia congelada do endereco de entrega e fiscal usado,
**so that** se o cliente alterar o endereco depois, os pedidos antigos preservem o historico real.

## Scope
### IN
- Alterar funcao `create_order` para aceitar `p_delivery_address_id UUID`
- Dentro da funcao, buscar o endereco e salvar como JSONB em `delivery_address_snapshot`
- Buscar endereco fiscal efetivo e salvar em `fiscal_address_snapshot`
- Alterar funcao `update_order` com mesma logica
- Frontend passa `delivery_address_id` ao chamar RPC

### OUT
- Alterar pedidos antigos (nao retroativo)
- Exibir snapshot no detalhe do pedido (pode ser story futura)

## Dependencies
- Story 7.1 — colunas `delivery_address_id`, `delivery_address_snapshot`, `fiscal_address_snapshot` no orders
- Story 7.6 — seletor de endereco integrado ao cart store

## Complexity
- **Estimate:** M
- **Points:** 5
- **Rationale:** Alterar 2 funcoes PL/pgSQL + ajustar chamada RPC no frontend

## Risks
- **R1:** Pedido sem endereco selecionado (cliente sem enderecos). **Mitigacao:** Campos nullable; snapshot fica NULL se nao houver endereco.
- **R2:** Snapshot grande demais. **Mitigacao:** JSONB armazena apenas os campos essenciais (~200 bytes).

## Acceptance Criteria
1. **Given** pedido criado com endereco selecionado, **When** inspeciono o pedido no banco, **Then** `delivery_address_snapshot` contem JSONB com label, rua, numero, bairro, cidade, UF, CEP
2. **Given** pedido criado com endereco selecionado, **When** inspeciono o pedido, **Then** `fiscal_address_snapshot` contem o endereco fiscal efetivo
3. **Given** endereco alterado pelo cliente apos a venda, **When** inspeciono o pedido antigo, **Then** snapshot preserva os dados originais
4. **Given** pedido criado sem endereco (cliente sem enderecos), **When** inspeciono, **Then** snapshots sao NULL (sem erro)
5. **Given** pedido editado (update_order), **When** endereco muda, **Then** snapshot e atualizado com o novo endereco

### Alteracao na funcao create_order
```sql
-- Novo parametro
p_delivery_address_id UUID DEFAULT NULL

-- Dentro do corpo, apos criar o pedido:
IF p_delivery_address_id IS NOT NULL THEN
  SELECT jsonb_build_object(
    'address_id', ca.id, 'label', ca.label,
    'street', ca.street, 'number', ca.number,
    'complement', ca.complement, 'neighborhood', ca.neighborhood,
    'city', ca.city, 'state', ca.state, 'cep', ca.cep
  ) INTO v_delivery_snapshot
  FROM client_addresses ca WHERE ca.id = p_delivery_address_id;

  -- Fiscal = explicito ou fallback
  SELECT jsonb_build_object(...)
  INTO v_fiscal_snapshot
  FROM client_addresses ca
  WHERE ca.client_id = p_client_id AND ca.is_active = true
    AND ca.is_fiscal = true
  LIMIT 1;

  -- Se nao tem fiscal explicito, usa o delivery como fallback
  IF v_fiscal_snapshot IS NULL THEN
    v_fiscal_snapshot := v_delivery_snapshot;
  END IF;

  UPDATE orders SET
    delivery_address_id = p_delivery_address_id,
    delivery_address_snapshot = v_delivery_snapshot,
    fiscal_address_snapshot = v_fiscal_snapshot
  WHERE id = v_order_id;
END IF;
```
