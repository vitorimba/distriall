## Story
**As a** dev do DistriAll,
**I want** que todas as transicoes usem os tokens de motion do DS,
**so that** a velocidade e curva de animacao sejam consistentes.

## Acceptance Criteria
1. Transicoes usam `var(--duration-*)` e `var(--ease-*)` em vez de `duration-200` do Tailwind
2. Dialog: fade + translateY(8px) + scale(0.98), duration-base (180ms)
3. Toast: fade + translateY(8px), duration-base (180ms)
4. Menu (BottomSheet items hover): `transition-colors` com `duration-instant` (80ms) — componente Menu separado nao existe no codebase; AC cobre apenas o hover dos itens do BottomSheet
5. BottomSheet: slide de baixo, duration-slow (240ms)
6. Hover em elementos interativos: duration-instant (80ms), ease-out
7. `@media (prefers-reduced-motion: reduce)` desliga animacoes (transition: none, animation: none)

## Pressupostos
- Motion tokens (`--duration-instant: 80ms`, `--duration-fast: 120ms`, `--duration-base: 180ms`, `--duration-slow: 240ms`, `--ease-out`, `--ease-in`, `--ease-in-out`, `--ease-spring`) ja estao definidos em `apps/web/src/app/globals.css` linhas 313-322 (`:root`). Nao e necessario `@import` de `packages/design-system/tokens/motion.css` — os tokens ja estao disponiveis no app
- Tailwind CSS v4 (este projeto usa `@import "tailwindcss"`) suporta valores arbitrarios com a sintaxe `duration-[var(--duration-base)]` para classes inline. Porem, a abordagem preferida e adicionar classes CSS puras em `globals.css` com `transition-duration: var(--duration-base)` (mais legivel e alinhado com o padrao do DS)
- `dialog.tsx` usa `@base-ui/react/dialog` com atributos `data-open:` e `data-closed:` do Tailwind. A mudança de duracao se faz substituindo `duration-100` por `[transition-duration:var(--duration-base)]` ou `duration-[var(--duration-base)]` no `className`
- `toast.tsx` usa `animate-in slide-in-from-bottom-2 fade-in duration-200` — substituir `duration-200` por `duration-[var(--duration-base)]`
- `bottom-sheet.tsx` usa `animate-in slide-in-from-bottom duration-200` — substituir `duration-200` por `duration-[var(--duration-base)]` (wait: AC5 diz `duration-slow` = 240ms, entao usar `duration-[var(--duration-slow)]`)
- Nao existe componente `menu.tsx` no codebase (`apps/web/src/components/ui/menu*.tsx` nao encontrado em pre-validacao). AC4 cobre apenas `transition-colors` dos itens do `BottomSheet` (hover), aplicando `duration-instant`
- `button.tsx` ja usa `transition-all` sem duration explicita — o objetivo e que o hover de botoes use `duration-instant`. Isso pode ser feito adicionando `transition-all` com duracao explicita via classe utilitaria `.hover-transition` ou modificando o `cva` base do button
- Nenhum componente novo deve ser criado — todas as mudancas sao ADAPT de arquivos existentes

## Dev Notes / Technical Notes

### Tokens de motion disponíveis (ja em globals.css `:root`)

```css
--duration-instant: 80ms;   /* hover, press, trocas de cor */
--duration-fast: 120ms;     /* tooltips, menus, scrim */
--duration-base: 180ms;     /* dialogs, toasts, transicoes padrao */
--duration-slow: 240ms;     /* bottom sheets, elementos grandes */
--duration-deliberate: 400ms; /* progress, graficos */

--ease-out: cubic-bezier(0.2, 0.8, 0.3, 1);
--ease-in: cubic-bezier(0.5, 0, 0.75, 0.4);
--ease-in-out: cubic-bezier(0.45, 0, 0.25, 1);
--ease-spring: cubic-bezier(0.34, 1.56, 0.64, 1);
```

### Task 1 — Classes utilitarias em globals.css

Adicionar ao final de `apps/web/src/app/globals.css`, apos os estilos existentes:

```css
/* ---- Motion utilities (DS tokens) ---- */
.hover-transition {
  transition-duration: var(--duration-instant);
  transition-timing-function: var(--ease-out);
}

@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```
