## Story
**As a** usuario com necessidades de acessibilidade,
**I want** que o app tenha foco visivel, labels corretos e contraste adequado,
**so that** eu consiga usar o sistema com teclado e leitores de tela.

## Acceptance Criteria
1. Focus ring: `outline 2px var(--focus-ring) offset 2` em todos os elementos interativos via `:focus-visible` em `globals.css`
2. aria-label em todos os IconButton (via `label` prop ou `aria-label` diretamente) — Story 5.6.1 ja cobriu os `size="icon"` existentes; esta story garante que novos interativos nao-textuais tambem tem label
3. aria-hidden em Skeleton (ja presente — `aria-hidden="true"` confirmado em skeleton.tsx) e em icones decorativos (`<Icon aria-hidden="true" />`)
4. Dialog prende foco (`@base-ui/react/dialog` gerencia focus trap nativamente), fecha com Esc (nativo do base-ui), devolve foco ao gatilho (gerenciado pelo base-ui)
5. Contraste AA 4.5:1 em todo texto — verificar especialmente `text-muted-foreground` vs `bg-background` e `bg-muted`
6. Alvo de toque >= 44px no mobile — token `--touch-target: 44px` ja definido em globals.css; garantir que botoes e links tem `min-height: var(--touch-target)` em viewports mobile

### Code Quality Assessment

Implementacao solida de acessibilidade declarativa. A abordagem de aria-hidden nos icones e correta — todos os icones auditados estao dentro de elementos com texto visivel ou aria-label explicito. O `*:focus-visible` global em @layer base esta bem posicionado e sobrescreve o outline generico apenas quando o elemento esta focado via teclado.

**Problema identificado e corrigido:** O input numerico do `quantity-stepper.tsx` usava a classe `outline-none` sem compensacao `focus-visible`, suprimindo o focus ring no campo numerico. Fix aplicado: adicionadas classes `focus-visible:outline-2 focus-visible:outline-[var(--focus-ring)] focus-visible:outline-offset-2` ao input.

**Concern Touch Targets:** A regra `@media (max-width: 767px) { button, a, [role="button"], [role="link"] { min-height: var(--touch-target) } }` aplica `min-height: 44px` a todos os botoes, incluindo os icon-only com `size="icon"` (geralmente 32-36px quadrado). Em mobile, esses botoes terao 44px de altura mas <44px de largura, resultando em alvo de toque nao-quadrado. Funcional para WCAG mas visualmente potencialmente deformado. Registrado como concern para revisao futura.

**Concern Contraste:** Validacao formal via Lighthouse/axe nao disponivel neste contexto. Analise dos tokens indica conformidade (muted-foreground #5F5A52 sobre background #F6F4F0 ~6.6:1 light; #A0A0AA sobre #0B0B0D ~10.4:1 dark), mas verificacao browser obrigatoria antes de producao.

**Concern Pagination:** Botoes de numeros de pagina nao tem aria-label contextual (ex: "Ir para pagina 3"). Texto numerico e lido por screen readers mas sem contexto de "pagina". WCAG 2.4.6 recomenda labels descritivos — medium concern.
