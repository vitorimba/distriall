## Story
**As a** Tiago,
**I want** ter 3 contas separadas ("Distrial RP", "Tiago", "Distrial Votoporanga") em um unico app,
**so that** eu nao precise de 3 celulares e 3 apps diferentes.

## Scope

### IN
- Tabelas `accounts` e `account_users` com RLS
- Helper functions SQL (get_user_account_ids, get_user_role_in_account, can_view_financial)
- Seed de 3 contas com permissoes por usuario
- Zustand store para conta ativa com persistencia localStorage
- Account Provider carregando contas do usuario
- Account Switcher no header (dropdown)
- Atualizar RLS de `users` para permitir admin ver membros da mesma conta

### OUT
- CRUD de contas (criar/editar/deletar contas — futuro)
- Gerenciamento de membros de conta (convidar/remover — futuro)
- RLS em tabelas de produto/pedido/financeiro (stories 1.4+)
- Configuracoes especificas por conta (settings JSONB — futuro)

## Dependencies
- **Story 1.2** (Autenticação) — COMPLETED. Tabela users, login, auth provider, proxy

## Complexity
- **Estimate:** M (Medium)
- **Points:** 5
- **Rationale:** 2 tabelas + 3 functions SQL + RLS + Zustand store + provider + UI component. Schema bem definido, complexidade moderada na integração do switcher com re-fetch.

## Risks
- **R1:** Seed usa UUIDs fixos — precisa usar os mesmos UUIDs da Story 1.2 seed. **Mitigacao:** Referenciar UUIDs constantes entre seeds.
- **R2:** RLS `FOR ALL` policy de admin pode conflitar com SELECT policy em `account_users`. **Mitigacao:** Usar policies separadas por operação (SELECT, INSERT, UPDATE, DELETE).
- **R3:** Troca de conta precisa limpar cache de dados — sem isso, usuario pode ver dados da conta anterior. **Mitigacao:** Zustand store clear + re-fetch no switchAccount.

## Acceptance Criteria
1. Tabela `accounts` criada com campos: id, name, owner_id, slug, is_active, settings (JSONB)
2. Tabela `account_users` criada com campos: account_id, user_id, role, can_view_financial, is_active
3. RLS configurado — usuario so ve dados das contas que tem acesso via `account_users`
4. UI com switcher de conta no header (dropdown/select) — troca sem logout, sem reload de pagina
5. 3 contas pre-criadas: "Distrial Rio Preto" (slug: distrial-rp), "Tiago" (slug: tiago), "Distrial Votoporanga" (slug: distrial-votoporanga)
6. Diego tem acesso a "Distrial RP" (vendedor, can_view_financial=true) e "Distrial Votoporanga" (vendedor, can_view_financial=false), sem acesso a "Tiago"
7. Joao tem acesso apenas a "Distrial Rio Preto" (entregador, can_view_financial=false)
8. Zustand store para conta ativa com persistencia (localStorage)
9. Todas as queries futuras filtram por `account_id` da conta ativa
10. Helper function SQL `get_user_account_ids()` retorna array de account_ids do usuario logado

## Dev Notes

### Schema SQL — Tabela `accounts`
```sql
CREATE TABLE public.accounts (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name TEXT NOT NULL,
  owner_id UUID NOT NULL REFERENCES public.users(id),
  slug TEXT NOT NULL UNIQUE, -- 'distrial-rp', 'tiago', 'distrial-votoporanga'
  is_active BOOLEAN NOT NULL DEFAULT true,
  settings JSONB DEFAULT '{}', -- configuracoes especificas da conta
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_accounts_owner ON public.accounts(owner_id);
CREATE INDEX idx_accounts_slug ON public.accounts(slug);
```

### Schema SQL — Tabela `account_users`
```sql
CREATE TABLE public.account_users (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  account_id UUID NOT NULL REFERENCES public.accounts(id) ON DELETE CASCADE,
  user_id UUID NOT NULL REFERENCES public.users(id) ON DELETE CASCADE,
  role TEXT NOT NULL CHECK (role IN ('admin', 'vendedor', 'entregador', 'visualizador')),
  can_view_financial BOOLEAN NOT NULL DEFAULT false,
  is_active BOOLEAN NOT NULL DEFAULT true,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),

  UNIQUE(account_id, user_id)
);

CREATE INDEX idx_account_users_account ON public.account_users(account_id);
CREATE INDEX idx_account_users_user ON public.account_users(user_id);
```

### Helper Functions SQL
```sql
-- Retorna todas as account_ids que o usuario logado tem acesso
CREATE OR REPLACE FUNCTION public.get_user_account_ids()
RETURNS UUID[] AS $$
  SELECT ARRAY(
    SELECT account_id
    FROM public.account_users
    WHERE user_id = auth.uid()
      AND is_active = true
  );
$$ LANGUAGE sql SECURITY DEFINER STABLE;

-- Retorna o role do usuario logado em uma conta especifica
CREATE OR REPLACE FUNCTION public.get_user_role_in_account(p_account_id UUID)
RETURNS TEXT AS $$
  SELECT role
  FROM public.account_users
  WHERE user_id = auth.uid()
    AND account_id = p_account_id
    AND is_active = true
  LIMIT 1;
$$ LANGUAGE sql SECURITY DEFINER STABLE;

-- Verifica se o usuario tem visibilidade financeira em uma conta
CREATE OR REPLACE FUNCTION public.can_view_financial(p_account_id UUID)
RETURNS BOOLEAN AS $$
  SELECT EXISTS(
    SELECT 1
    FROM public.account_users
    WHERE user_id = auth.uid()
      AND account_id = p_account_id
      AND is_active = true
      AND (role = 'admin' OR can_view_financial = true)
  );
$$ LANGUAGE sql SECURITY DEFINER STABLE;
```

### RLS Policies — `accounts`
```sql
ALTER TABLE public.accounts ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Users can view accounts they belong to"
  ON public.accounts FOR SELECT
  USING (id = ANY(get_user_account_ids()));
```

### RLS Policies — `account_users`
```sql
ALTER TABLE public.account_users ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Users can view memberships of their accounts"
  ON public.account_users FOR SELECT
  USING (account_id = ANY(get_user_account_ids()));

CREATE POLICY "Admins can manage account memberships"
  ON public.account_users FOR ALL
  USING (get_user_role_in_account(account_id) = 'admin')
  WITH CHECK (get_user_role_in_account(account_id) = 'admin');
```

### Zustand Store — Account
```typescript
// apps/web/src/stores/account-store.ts
import { create } from 'zustand';
import { persist } from 'zustand/middleware';

interface Account {
  id: string;
  name: string;
  slug: string;
  role: string;          // role do usuario NESTA conta
  can_view_financial: boolean;
}

interface AccountStore {
  activeAccountId: string | null;
  accounts: Account[];
  setActiveAccount: (id: string) => void;
  setAccounts: (accounts: Account[]) => void;
  getActiveAccount: () => Account | undefined;
}

export const useAccountStore = create<AccountStore>()(
  persist(
    (set, get) => ({
      activeAccountId: null,
      accounts: [],
      setActiveAccount: (id) => set({ activeAccountId: id }),
      setAccounts: (accounts) => set({ accounts, activeAccountId: accounts[0]?.id ?? null }),
      getActiveAccount: () => get().accounts.find(a => a.id === get().activeAccountId),
    }),
    { name: 'distriall-account' }
  )
);
```
