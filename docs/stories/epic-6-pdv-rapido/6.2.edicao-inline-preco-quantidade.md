# Story 6.2: Edicao Inline de Preco e Quantidade no Carrinho

## Status
Draft

## Executor Assignment
executor: "@dev"
quality_gate: "@qa"

## Story
**As a** vendedor (Tiago ou Diego),
**I want** editar a quantidade e o preco de venda de um item diretamente no carrinho, digitando o valor,
**so that** eu consiga ajustar quantidades grandes (ex: 25 unidades) sem precisar clicar 25 vezes, e negociar precos especiais na hora.

## Scope

### IN
- Quantidade editavel: toque no numero de quantidade abre input numerico para digitacao direta
- Preco editavel: toque no preco unitario abre input para alterar valor de venda
- Validacoes: quantidade minima 1, preco minimo 0.01
- Totais recalculados em tempo real ao editar
- Funciona tanto na pagina de novo pedido quanto na de edicao

### OUT
- Edicao de preco no catalogo/grid (preco e editado apenas no carrinho)
- Salvar preco customizado permanentemente no cadastro do cliente (futuro)
- Desconto percentual (futuro)
- Historico de alteracoes de preco (futuro)

## Dependencies
- **Story 6.1** (Catalogo Visual) — pode ser implementada em paralelo, mas idealmente apos 6.1
- **Story 2.1** (Lancamento Pedidos) — COMPLETED. OrderItemList, cart store

## Complexity
- **Estimate:** M (Medium)
- **Points:** 5
- **Rationale:** Modificacao do OrderItemList existente. Adicionar estados de edicao (inline input vs display). Novo metodo `updatePrice` no cart store. Validacoes simples. Sem mudancas no backend (preco ja e enviado do front).

## Risks
- **R1:** Edicao inline pode ser dificil de usar em telas pequenas. **Mitigacao:** Input numerico nativo do mobile, area de toque adequada.
- **R2:** Vendedor pode alterar preco por engano. **Mitigacao:** Preco original visivel como referencia (riscado ou em texto menor).
- **R3:** Preco editado nao persiste entre sessoes (so vale para aquele pedido). **Mitigacao:** Esperado — preco permanente e via cadastro client_prices.

## Acceptance Criteria

1. **Given** item no carrinho, **When** vendedor toca na quantidade exibida, **Then** abre input numerico editavel no lugar do numero, com o valor atual pre-preenchido
2. **Given** input de quantidade aberto, **When** vendedor digita novo valor (ex: 25) e confirma (blur ou Enter), **Then** quantidade e atualizada e total da linha recalculado
3. **Given** input de quantidade aberto, **When** vendedor digita 0 ou valor invalido, **Then** item e removido do carrinho (quantidade 0) ou input rejeita (valor negativo/texto)
4. **Given** item no carrinho, **When** vendedor toca no preco unitario, **Then** abre input numerico editavel com o preco atual pre-preenchido
5. **Given** input de preco aberto, **When** vendedor digita novo valor e confirma, **Then** preco unitario e atualizado, total da linha e subtotal recalculados
6. **Given** preco foi editado manualmente, **When** item exibe no carrinho, **Then** preco original aparece como referencia visual (ex: riscado ou menor) ao lado do preco editado
7. **Given** botoes +/- existentes no carrinho, **When** vendedor usa +/-, **Then** continuam funcionando normalmente (sem regressao)

### Padroes de interacao
- Focus ring visivel: `outline: 2px solid var(--accent)` — ACESSIBILIDADE OBRIGATORIA
- Input numerico: usar `inputMode="decimal"` (mobile) + `type="text"` com mascara (evitar spinners nativos de `type="number"`)
- Transicao suave entre modo display e modo edicao (fade 120ms)
- Respeitar `prefers-reduced-motion`

### Regras de design
- Manter layout existente do `order-item-list.tsx` — apenas tornar qty/preco clicaveis
- Preco original riscado em `var(--text-secondary)` + `var(--fs-xs)` quando editado
- Preco editado em `var(--accent-fg)` para sinalizar alteracao
- Botoes +/- continuam com mesmo estilo: `var(--surface-card)` fundo, `var(--border-subtle)` borda, 40px size
- Dark/Light theme: usar apenas tokens CSS, NUNCA hex hardcoded

### Novo metodo no Cart Store
```typescript
updatePrice: (variantId: string, price: number) => {
  set((state) => ({
    items: state.items.map((i) =>
      i.variantId === variantId
        ? { ...i, unitPrice: price, originalPrice: i.originalPrice ?? i.unitPrice }
        : i
    ),
  }));
}
```

### CartItem — campo adicional
```typescript
interface CartItem {
  // ... campos existentes
  originalPrice?: number; // preco original antes de edicao manual (para exibir riscado)
}
```

### UX de edicao inline
- Toque no numero → input aparece no lugar (mesmo tamanho, sem layout shift)
- Blur ou Enter → confirma edicao
- Escape → cancela edicao (volta ao valor anterior)
- Input com `inputMode="decimal"` para teclado numerico no mobile
- Select all on focus para facilitar substituicao do valor
