## Story
**As a** vendedor (Tiago ou Diego),
**I want** ver todos os produtos disponiveis em cards grandes assim que seleciono o cliente, e adicionar ao pedido com um simples toque,
**so that** eu consiga lancar pedidos muito mais rapido sem precisar digitar o nome de cada produto.

## Scope

### IN
- Grid de cards de produtos exibidos automaticamente apos selecionar cliente
- Cada card mostra: nome do produto, variante, preco efetivo (customizado ou padrao)
- 1 clique/toque no card = adiciona 1 unidade ao carrinho (ou incrementa se ja existe)
- Badge de quantidade no card quando produto ja esta no carrinho
- Cards grandes e touch-friendly (minimo 80px altura)
- Campo de busca mantido como filtro do grid (digitar filtra os cards visiveis)
- Carrega todos os produtos ativos da conta com suas variantes
- Respeita priceMap do cliente (precos customizados destacados visualmente)

### OUT
- Edicao de preco/quantidade inline (Story 6.2)
- Categorias/abas de produtos (futuro)
- Imagens nos cards de produto (futuro)
- Reordenacao de produtos por frequencia de uso (futuro)

## Dependencies
- **Story 2.1** (Lancamento Pedidos) — COMPLETED. Cart store, ProductSearch, pagina novo pedido
- **Story 1.4** (Produtos) — COMPLETED. products, product_variants
- **Story 1.5** (Clientes) — COMPLETED. client_prices, priceMap

## Complexity
- **Estimate:** L (Large)
- **Points:** 8
- **Rationale:** Novo componente ProductCatalog substituindo/complementando ProductSearch. Query para carregar todos produtos ativos. Integracao com cart store existente (addItem). Grid responsivo. Filtro por busca. Badge de quantidade. Feedback visual de toque.

## Risks
- **R1:** Conta com muitos produtos (100+) pode gerar grid longo. **Mitigacao:** Scroll virtual ou agrupamento simples. Na pratica distribuidoras tem 20-60 produtos ativos.
- **R2:** Produtos com muitas variantes podem poluir o grid. **Mitigacao:** Cada variante e um card separado (mesmo modelo atual do search).
- **R3:** Performance no mobile com muitos cards. **Mitigacao:** Carregar 1x no mount, sem paginacao (dataset pequeno).

## Acceptance Criteria

1. **Given** cliente selecionado, **When** pagina de novo pedido carrega, **Then** todos os produtos ativos da conta aparecem em grid de cards (sem precisar digitar nada)
2. **Given** grid de produtos visivel, **When** vendedor toca/clica em um card, **Then** produto e adicionado ao carrinho com quantidade 1 (ou quantidade incrementa +1 se ja estava no carrinho)
3. **Given** produto ja no carrinho com quantidade N, **When** vendedor toca no card novamente, **Then** quantidade vai para N+1 e badge no card mostra quantidade atual
4. **Given** cliente com precos customizados, **When** grid carrega, **Then** cards mostram preco efetivo (customizado) e precos customizados tem destaque visual (cor diferente)
5. **Given** grid de produtos visivel, **When** vendedor digita no campo de busca, **Then** cards sao filtrados em tempo real pelo nome do produto/variante
6. **Given** nenhum texto na busca, **When** grid esta visivel, **Then** todos os produtos aparecem (busca vazia = sem filtro)
7. **Given** qualquer tamanho de tela, **When** grid renderiza, **Then** cards sao responsivos (2 colunas mobile, 3+ desktop) e touch-friendly (area de toque minima 44x44px)

## Design System Compliance (NON-NEGOTIABLE)

### Componentes UI obrigatorios (REUSE do DS existente)
- `Card` + `CardContent` — container de cada produto no grid
- `SearchField` — campo de busca/filtro (NAO usar Input cru com icone manual)
- `Badge` — badge de quantidade no card quando produto esta no carrinho
- `Money` — exibicao de preco (com classe `.num` para tabular-nums)
- `Skeleton` — estado de loading enquanto carrega produtos
- `EmptyState` — se conta nao tem produtos ativos cadastrados

### Tokens obrigatorios (NUNCA hardcodar cores/espacamentos)
```css
/* Surfaces */
background: var(--surface-card);          /* fundo do card */
background: var(--surface-hover);         /* hover/active state do card */

/* Texto */
color: var(--text-primary);               /* nome do produto */
color: var(--text-secondary);             /* nome da variante */
color: var(--accent-fg);                  /* preco customizado destacado */

/* Espacamento */
gap: var(--stack-gap);                    /* gap entre cards no grid */
padding: var(--card-pad);                 /* padding interno do card */
min-height: var(--touch-target);          /* 44px minimo area de toque */

/* Bordas e sombras */
border-color: var(--border-subtle);       /* borda do card */
border-radius: var(--radius-ds-md);       /* 12px */
box-shadow: var(--shadow-card);           /* sombra sutil */

/* Feedback de toque */
transition: var(--duration-instant) var(--ease-out);  /* 80ms hover */
transform: scale(0.97);                  /* press feedback */

/* Badge de quantidade */
background: var(--accent);               /* fundo laranja */
color: white;                            /* texto do badge */
border-radius: var(--radius-full);        /* circular */
```

### Grid responsivo
```css
/* Usar CSS Grid com tokens, NAO Tailwind arbitrario */
display: grid;
grid-template-columns: repeat(2, 1fr);   /* 2 colunas mobile */
gap: var(--stack-gap);

@media (min-width: 768px) {              /* var(--bp-mobile) */
  grid-template-columns: repeat(3, 1fr); /* 3 colunas desktop */
}
```

### 3 estados obrigatorios
1. **Loading** → `Skeleton` (grid de cards placeholder)
2. **Vazio** → `EmptyState` (icon + "Nenhum produto cadastrado" + acao)
3. **Erro** → `Alert` (tone="danger") com retry

### Regras de design
- Touch target minimo 44px (`var(--touch-target)`) — INVIOLAVEL
- Orange apenas no badge de quantidade e CTA, nunca nos cards
- Precos sempre com componente `Money` e classe `.num` (tabular-nums, alinhado a direita)
- Preco customizado: cor `var(--accent-fg)` para diferenciar do padrao
- Animacao de toque: apenas `transform` e `opacity` (nunca animar layout)
- Respeitar `prefers-reduced-motion` — sem scale feedback se motion reduzido
- Dark/Light theme: usar apenas tokens CSS, NUNCA hex hardcoded
