## Story
**As a** Tiago,
**I want** registrar devolucao de itens de um pedido ja entregue, com abatimento automatico no acerto,
**so that** eu nao precise excluir e relancar o pedido inteiro quando ha devolucao parcial.

## Acceptance Criteria
1. Acao "Registrar Devolucao" disponivel em pedido com status "Entregue"
2. Selecionar quais produtos e quantidades devolvidas (ate o maximo do item)
3. Pedido recalcula automaticamente: novo total, novo lucro (subtrai valor devolvido)
4. Registro de devolucao com motivo (campo texto obrigatorio) e data automatica
5. Valor devolvido refletido no acerto semanal da conta (via `order_items.is_returned` e `returned_quantity`)
6. Historico de devolucoes visivel no detalhe do pedido
7. Itens devolvidos nao contam na consolidacao de carregamento (Story 2.3)

## Dev Notes

### Database: Campos de Devolucao nos order_items

Os campos ja existem na tabela `order_items` (criados no Epic 1):

```sql
-- Campos relevantes em order_items:
is_returned BOOLEAN NOT NULL DEFAULT false,
returned_quantity NUMERIC(10,3) DEFAULT 0,
return_reason TEXT,
returned_at TIMESTAMPTZ,
```

**Logica de devolucao parcial:**
- Item com 10 unidades, devolvidas 3: `is_returned = false`, `returned_quantity = 3`
- Item com 10 unidades, devolvidas 10: `is_returned = true`, `returned_quantity = 10`
- Quantidade efetiva = `quantity - returned_quantity`

### Supabase Function: `process_return`

```sql
CREATE OR REPLACE FUNCTION public.process_return(
  p_order_id UUID,
  p_items JSONB -- [{ "order_item_id": "uuid", "returned_quantity": 3, "reason": "produto danificado" }]
) RETURNS UUID AS $$
DECLARE
  v_item JSONB;
  v_order_item RECORD;
  v_total_return_value NUMERIC := 0;
  v_total_return_cost NUMERIC := 0;
  v_current_order RECORD;
BEGIN
  -- Validate order status
  SELECT * INTO v_current_order FROM public.orders WHERE id = p_order_id;
  IF v_current_order.status != 'entregue' THEN
    RAISE EXCEPTION 'Returns can only be processed on delivered orders. Current status: %', v_current_order.status;
  END IF;

  -- Process each returned item
  FOR v_item IN SELECT * FROM jsonb_array_elements(p_items)
  LOOP
    SELECT * INTO v_order_item FROM public.order_items
    WHERE id = (v_item->>'order_item_id')::UUID;

    -- Validate quantity
    IF (v_item->>'returned_quantity')::NUMERIC > (v_order_item.quantity - v_order_item.returned_quantity) THEN
      RAISE EXCEPTION 'Cannot return more than available quantity for item %', v_order_item.product_name;
    END IF;

    -- Update item
    UPDATE public.order_items SET
      returned_quantity = returned_quantity + (v_item->>'returned_quantity')::NUMERIC,
      is_returned = CASE
        WHEN returned_quantity + (v_item->>'returned_quantity')::NUMERIC >= quantity THEN true
        ELSE false
      END,
      return_reason = v_item->>'reason',
      returned_at = now()
    WHERE id = (v_item->>'order_item_id')::UUID;

    -- Accumulate return values
    v_total_return_value := v_total_return_value +
      ((v_item->>'returned_quantity')::NUMERIC * v_order_item.unit_price);
    v_total_return_cost := v_total_return_cost +
      ((v_item->>'returned_quantity')::NUMERIC * v_order_item.cost_price);
  END LOOP;

  -- Recalculate order totals
  UPDATE public.orders SET
    subtotal = subtotal - v_total_return_value,
    total_cost = total_cost - v_total_return_cost,
    profit = (subtotal - v_total_return_value) - (total_cost - v_total_return_cost),
    total = (subtotal - v_total_return_value) - discount,
    updated_at = now()
  WHERE id = p_order_id;

  RETURN p_order_id;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;
```

### API Route: POST /api/orders/[id]/return

```typescript
// apps/web/src/app/api/orders/[id]/return/route.ts

export async function POST(
  request: Request,
  { params }: { params: { id: string } }
) {
  const { items } = await request.json();
  // items: [{ order_item_id: string, returned_quantity: number, reason: string }]

  const supabase = createRouteHandlerClient({ cookies });

  const { data, error } = await supabase.rpc('process_return', {
    p_order_id: params.id,
    p_items: JSON.stringify(items),
  });

  if (error) {
    return Response.json({ error: error.message }, { status: 400 });
  }

  // Fetch updated order
  const { data: order } = await supabase
    .from('orders')
    .select('*, items:order_items(*)')
    .eq('id', params.id)
    .single();

  return Response.json({ order });
}
```

### Integracao com Acerto Semanal (Epic 3 - Futuro)

O acerto semanal (Story 3.4) deve:
1. Usar `orders.total` que ja esta recalculado pela function `process_return`
2. O campo `settlements.total_returns` deve somar o valor das devolucoes do periodo
3. Query para total de devolucoes:

```sql
SELECT SUM(
  oi.returned_quantity * oi.unit_price
) as total_returns
FROM order_items oi
JOIN orders o ON oi.order_id = o.id
WHERE o.account_id = $1
  AND oi.returned_at BETWEEN $2 AND $3
  AND oi.returned_quantity > 0;
```

### Validacoes

1. Pedido DEVE ter status `entregue` para aceitar devolucao
2. `returned_quantity` NAO pode exceder `quantity - already_returned_quantity`
3. `reason` (motivo) e obrigatorio, minimo 5 caracteres
4. Pelo menos 1 item deve ser selecionado para devolucao
5. Quantidade devolvida deve ser > 0
