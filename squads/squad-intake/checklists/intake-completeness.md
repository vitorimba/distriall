# Intake Completeness Checklist

## Propósito
Verificar se o intake de um cliente está completo o suficiente para gerar relatório e fazer handoff.

## Critérios de Completude

### Bloco 1: Negócio (peso: 15%)
- [ ] Nome da empresa identificado
- [ ] Setor/indústria definido
- [ ] Modelo de negócio claro
- [ ] Público-alvo descrito
- [ ] Estágio do negócio identificado

### Bloco 2: Problema (peso: 25%)
- [ ] Problema principal articulado em 1-3 frases
- [ ] Processo atual descrito (como resolvem hoje)
- [ ] Impacto quantificado (custo, tempo, risco)
- [ ] Urgência classificada
- [ ] Tentativas anteriores documentadas

### Bloco 3: Solução (peso: 20%)
- [ ] Visão do cenário ideal descrita
- [ ] Usuários finais identificados
- [ ] Features essenciais listadas (máx 5)
- [ ] Integrações necessárias mapeadas
- [ ] Plataformas definidas (mobile/web/desktop)

### Bloco 4: Objetivos e Sucesso (peso: 20%)
- [ ] Objetivos são outcomes de NEGÓCIO (não deliverables)
- [ ] Pelo menos 1 KPI com baseline e target
- [ ] Prazo para resultados definido
- [ ] Critério de fracasso documentado
- [ ] Decisor de sucesso identificado

### Bloco 5: Restrições (peso: 15%)
- [ ] Budget: range definido
- [ ] Prazo: expectativa documentada
- [ ] Equipe: disponibilidade mapeada
- [ ] Compliance: requisitos identificados (ou confirmado que não há)

### Bloco 6: Complementar (peso: 5%)
- [ ] Stakeholders listados com papéis
- [ ] Canal de comunicação definido
- [ ] Disponibilidade para reuniões

## Scoring

**Score = soma ponderada dos blocos**

| Score | Classificação | Ação |
|-------|--------------|------|
| >= 85% | COMPLETO | Pode gerar relatório e handoff |
| 70-84% | QUASE COMPLETO | Gerar relatório com flags de gaps |
| 50-69% | INCOMPLETO | Follow-up obrigatório antes de relatório |
| < 50% | INSUFICIENTE | Reavaliar — pode precisar de nova reunião |

## Veto Gates

| Condição | Ação |
|----------|------|
| Problema principal não articulado | BLOCK — sem isso, nada avança |
| Zero métricas de sucesso | BLOCK — sem métrica, sem critério de entrega |
| Budget completamente indefinido | BLOCK — impossível propor sem range |
| Decisor não identificado | FLAG — alto risco de cancelamento |
