# Checklist de Compliance LGPD

Lei Geral de Protecao de Dados Pessoais (Lei 13.709/2018).
Todos os requisitos mapeados para acoes verificaveis.

---

## 1. Principios (Art. 6)

### Finalidade
- [ ] Cada dado pessoal coletado tem finalidade especifica e documentada
- [ ] Finalidade informada ao titular ANTES da coleta
- [ ] Dados nao sao usados para finalidade diferente da declarada

### Adequacao
- [ ] Processamento e compativel com a finalidade informada
- [ ] Nao ha processamento que contradiga a finalidade original

### Necessidade (Minimizacao)
- [ ] Coleta-se APENAS os dados estritamente necessarios
- [ ] Campos opcionais claramente marcados
- [ ] Revisao periodica: dados coletados ainda sao necessarios?
- [ ] Dados excessivos identificados e removidos

### Livre Acesso
- [ ] Titular pode consultar seus dados a qualquer momento
- [ ] Consulta e gratuita e em formato acessivel
- [ ] Prazo de resposta: ate 15 dias

### Qualidade dos Dados
- [ ] Dados mantidos atualizados
- [ ] Mecanismo para titular atualizar seus dados
- [ ] Dados incorretos podem ser corrigidos

### Transparencia
- [ ] Informacoes claras sobre como dados sao processados
- [ ] Linguagem acessivel (nao juridiquês)
- [ ] Facil de encontrar (nao escondido em paginas internas)

### Seguranca
- [ ] Medidas tecnicas implementadas (criptografia, controle de acesso)
- [ ] Medidas administrativas implementadas (politicas, treinamento)
- [ ] Protecao contra acesso nao autorizado
- [ ] Protecao contra destruicao acidental ou ilicita

### Prevencao
- [ ] Medidas para prevenir danos ao titular
- [ ] Avaliacoes de risco realizadas
- [ ] Plano de resposta a incidentes definido

### Nao Discriminacao
- [ ] Processamento nao gera discriminacao ilicita
- [ ] Dados sensiveis nao usados para discriminar
- [ ] Decisoes automatizadas revisadas por vies

### Responsabilizacao e Prestacao de Contas
- [ ] Documentacao de compliance mantida atualizada
- [ ] Evidencias de conformidade armazenadas
- [ ] Disponivel para ANPD quando solicitado

---

## 2. Bases Legais (Art. 7)

- [ ] Base legal identificada e documentada para CADA processamento
- [ ] Mapeamento: dado → finalidade → base legal

### Consentimento (Art. 7, I + Art. 8)
- [ ] Consentimento livre, informado e inequivoco
- [ ] Consentimento em destaque (nao checkbox pre-marcado)
- [ ] Finalidades especificas informadas ao consentir
- [ ] Consentimento registrado com data e escopo
- [ ] Facil de revogar (tao facil quanto foi conceder)
- [ ] Revogacao efetiva (dados deixam de ser processados)
- [ ] Consentimento de menores: responsavel legal consentiu? (Art. 14)

### Interesse Legitimo (Art. 7, IX + Art. 10)
- [ ] LIA (Legitimate Interest Assessment) documentada
- [ ] Interesse legitimo claramente descrito
- [ ] Nao prevalece sobre direitos do titular
- [ ] Dados minimizados para o interesse legitimo
- [ ] RIPD elaborado quando baseado em interesse legitimo

### Outras Bases
- [ ] Obrigacao legal: lei especifica identificada
- [ ] Execucao de contrato: contrato formalizado
- [ ] Exercicio regular de direitos: processo judicial/administrativo
- [ ] Protecao da vida: situacao de emergencia documentada
- [ ] Tutela da saude: profissional de saude ou autoridade sanitaria
- [ ] Protecao do credito: legislacao especifica aplicavel

---

## 3. Direitos do Titular (Art. 18)

### Confirmacao e Acesso (Art. 18, I e II)
- [ ] Endpoint/funcionalidade para titular acessar seus dados
- [ ] Dados retornados em formato legivel
- [ ] Resposta em ate 15 dias

### Correcao (Art. 18, III)
- [ ] Titular pode corrigir dados incompletos ou inexatos
- [ ] Correcao propagada para terceiros que receberam os dados

### Anonimizacao, Bloqueio ou Eliminacao (Art. 18, IV)
- [ ] Dados desnecessarios podem ser anonimizados
- [ ] Dados excessivos podem ser eliminados
- [ ] Dados tratados em desconformidade podem ser bloqueados

### Portabilidade (Art. 18, V)
- [ ] Titular pode solicitar portabilidade dos dados
- [ ] Dados fornecidos em formato estruturado (JSON, CSV)
- [ ] Portabilidade para outro fornecedor de servico

### Eliminacao (Art. 18, VI)
- [ ] Titular pode solicitar exclusao de seus dados
- [ ] Exclusao efetiva (hard delete ou anonimizacao irreversivel)
- [ ] Confirmacao de exclusao fornecida ao titular
- [ ] Excecoes documentadas (obrigacao legal de retencao)

### Informacao sobre Compartilhamento (Art. 18, VII)
- [ ] Titular pode saber com quem seus dados foram compartilhados
- [ ] Lista de terceiros/parceiros disponivel

### Revogacao de Consentimento (Art. 18, IX)
- [ ] Mecanismo simples para revogar consentimento
- [ ] Revogacao gratuita e facilitada
- [ ] Efeitos da revogacao informados ao titular

### Oposicao (Art. 18, § 2º)
- [ ] Titular pode se opor a processamento em certas situacoes
- [ ] Oposicao avaliada caso a caso

---

## 4. Dados Sensiveis (Art. 11)

- [ ] Dados sensiveis identificados e catalogados
  - Origem racial/etnica
  - Convicao religiosa
  - Opiniao politica
  - Filiacao sindical
  - Dados de saude
  - Vida sexual
  - Dado genetico/biometrico
- [ ] Consentimento especifico e destacado para dados sensiveis
- [ ] Medidas de seguranca adicionais para dados sensiveis
- [ ] Acesso restrito a quem realmente precisa

---

## 5. Dados de Menores (Art. 14)

- [ ] Consentimento do responsavel legal obtido
- [ ] Verificacao de idade implementada
- [ ] Informacoes em linguagem adequada a criancas
- [ ] Coleta do minimo necessario
- [ ] Dados nao usados para marketing sem consentimento

---

## 6. Transferencia Internacional (Art. 33)

- [ ] Transferencias internacionais mapeadas
- [ ] Mecanismo legal adequado implementado:
  - [ ] Pais com protecao adequada (decisao ANPD)
  - [ ] Clausulas-padrao contratuais
  - [ ] Consentimento especifico do titular
  - [ ] Normas corporativas globais
- [ ] Documentacao da transferencia mantida

---

## 7. Governanca e Organizacao

### Encarregado / DPO (Art. 41)
- [ ] DPO/Encarregado designado
- [ ] Identidade e contato publicados (site, politica de privacidade)
- [ ] Canal de comunicacao com titulares funcional
- [ ] DPO com autonomia e recursos adequados

### Politica de Privacidade
- [ ] Politica de privacidade publicada e acessivel
- [ ] Linguagem clara e simples
- [ ] Contem: identidade do controlador, finalidades, base legal, direitos
- [ ] Atualizada quando processamento muda
- [ ] Versionada com data de ultima atualizacao

### RIPD — Relatorio de Impacto (Art. 38)
- [ ] RIPD elaborado para processamentos de alto risco
- [ ] Contem: tipos de dados, metodologia, medidas de seguranca
- [ ] Disponivel para ANPD quando solicitado
- [ ] Atualizado periodicamente

### Registro de Operacoes (Art. 37)
- [ ] Registro de todas operacoes de tratamento mantido
- [ ] Inclui: categorias de dados, finalidades, bases legais
- [ ] Atualizado quando operacoes mudam

---

## 8. Seguranca e Boas Praticas (Art. 46)

### Medidas Tecnicas
- [ ] Criptografia em transito (TLS 1.2+)
- [ ] Criptografia em repouso
- [ ] Controle de acesso baseado em funcao (RBAC)
- [ ] Logs de acesso a dados pessoais
- [ ] Backup com criptografia
- [ ] Pseudonimizacao quando viavel
- [ ] Anonimizacao para analytics

### Medidas Administrativas
- [ ] Politica de seguranca da informacao
- [ ] Treinamento de colaboradores sobre LGPD
- [ ] Acordo de confidencialidade com colaboradores
- [ ] Revisao periodica de acessos

---

## 9. Incidentes de Seguranca (Art. 48)

### Notificacao a ANPD
- [ ] Procedimento de notificacao documentado
- [ ] Prazo: "prazo razoavel" (recomendado 72 horas, conforme GDPR)
- [ ] Conteudo da notificacao:
  - [ ] Natureza dos dados afetados
  - [ ] Titulares envolvidos
  - [ ] Medidas tecnicas de seguranca existentes
  - [ ] Riscos relacionados
  - [ ] Medidas adotadas para reverter ou mitigar

### Notificacao ao Titular
- [ ] Titulares notificados quando incidente pode causar risco/dano
- [ ] Comunicacao clara sobre o que aconteceu e acoes tomadas

### Plano de Resposta
- [ ] Equipe de resposta a incidentes definida
- [ ] Procedimento de contencao documentado
- [ ] Template de notificacao preparado
- [ ] Simulacao de incidente realizada (tabletop exercise)

---

## 10. Terceiros e Processadores (Art. 39)

- [ ] Contratos com operadores/processadores incluem clausulas de LGPD
- [ ] Operadores seguem instrucoes documentadas
- [ ] Due diligence de seguranca em fornecedores
- [ ] Sub-processadores autorizados pelo controlador
- [ ] Responsabilidades claras (controlador vs operador)

---

## Score de Compliance

| Score | Status | Acao |
|-------|--------|------|
| 90-100% | COMPLIANT | Manter e atualizar periodicamente |
| 75-89% | SUBSTANTIALLY COMPLIANT | Corrigir gaps menores |
| 60-74% | PARTIALLY COMPLIANT | Plano de remediacao necessario |
| 40-59% | NON-COMPLIANT | Risco legal significativo |
| < 40% | CRITICALLY NON-COMPLIANT | Risco de multa iminente |

### Sancoes LGPD (Art. 52)
- Advertencia
- Multa simples: ate 2% do faturamento (limite R$ 50 milhoes por infracao)
- Multa diaria
- Publicizacao da infracao
- Bloqueio/eliminacao dos dados
- Suspensao do exercicio da atividade de tratamento
